# EscrowScope v0.4: read the statement (design)

Date: 2026-07-30. Status: approved, not built yet.

## What v0.4 does

Right now you have to type your escrow numbers into three fields by hand.
In v0.4 you paste the text of your annual escrow analysis statement, click
"Extract numbers", and the app fills in the fields for you. You check that
the numbers look right, fix anything that is off, then click "Check the math"
like before. The engine and the verdict do not change at all.

The extractor is a mock in this version. It returns the numbers from a
built-in sample statement, in the exact JSON shape a real AI extractor will
return later. That makes v0.4.5 (the real AI call behind a serverless
function) a swap of one function body, with zero changes anywhere else.

Why mock first: the AI version needs a serverless function to hide the API
key, because GitHub Pages is static and any key in the page source is public.
Building the whole paste-extract-verify-verdict flow first means nothing can
block shipping, and the risky new infrastructure becomes its own small step.

## User flow

1. Visitor opens the page. New section at the top: "Paste your escrow
   statement" with a textarea, a "Load sample" button, and an
   "Extract numbers" button.
2. They paste text (or click "Load sample" to fill the box with the built-in
   sample statement).
3. Click "Extract numbers". The starting balance, monthly deposit, and bills
   fields fill in automatically.
4. They eyeball the fields. This is deliberate: extracted numbers never skip
   straight to a verdict, because extraction (especially AI extraction later)
   can be wrong. The human confirms before the math runs.
5. Click the existing "Check the math" button. Verdict renders as in v0.3.

## Files

- `sample-statement.txt` (new): a realistic fake annual escrow analysis,
  written like a real servicer letter. Uses the numbers from test case #1
  (starting balance $1,500, monthly deposit $400, property tax $1,800 in May,
  homeowners insurance $1,200 in July, property tax $1,800 in November), so
  the correct output is already hand-verified: $300 surplus, refund required.
- `extract.js` (new): one exported function, `extractStatement(text)`.
  Returns `{ startingBalance, monthlyDeposit, bills }` on success, `null` if
  it cannot read the text. In v0.4 it recognizes the sample statement and
  returns its numbers; anything else returns `null`. The return shape is the
  contract the future AI extractor must also honor.
- `index.html` (changed): the paste section, the two new buttons, and the
  wiring that writes extracted values into the existing input fields.
- `tests.js` (changed): one new test. Sample statement text in,
  test case #1 numbers out. Same pattern as the four existing engine tests.

## Error handling

- Empty paste box + "Extract numbers": message "Paste a statement first
  (or click Load sample)."
- Text the mock does not recognize: honest message that v0.4 is demo mode
  and only reads the sample format, and that real statements need the AI
  step coming in v0.4.5. No fake success, no silent failure.

## Out of scope (later rungs)

- v0.4.5: real extraction. LLM call behind a free serverless function
  (Vercel), free-tier model, key in an environment variable. Known risks to
  handle then: rate limits on free tiers, anyone burning the public demo's
  quota, and wrong extractions (mitigated by the verify-before-verdict flow
  which is already built in v0.4).
- PDF upload. Paste text only for now.
- Multiple servicer formats.

## Done means

A visitor on the live site clicks "Load sample", clicks "Extract numbers",
watches the fields fill in, clicks "Check the math", and gets the correct
$300 over-collection verdict. Tests pass 5/5. Deployed on GitHub Pages.
